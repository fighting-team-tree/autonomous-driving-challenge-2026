## D-001. 저장소를 public으로 유지한다 {#d-001}

**결정** — 대회 기간 중에도 저장소를 공개로 둔다.

**이유** — 후원 기업 15곳 면접 기회가 걸려 있고, 정리된 실험 로그는 그 자체로 포트폴리오다.
비공개로 두면 GitHub Pages가 동작하지 않는다 (org가 free plan이라 private Pages는
GitHub Team 이상 필요).

**감수하는 리스크** — 경쟁팀 165개에 가설이 실시간 노출된다. 주최측이
[작년 표절 적발 사례](competition/briefing.md#plagiarism)를 명시적으로 경고했고,
본선 4팀은 코드 검증을 받는다.

**완화** — D-002 참조.

## D-002. 복붙 가능한 설정값은 문서에 쓰지 않는다 {#d-002}

**결정** — 공개 문서에는 **가설·설계 의도·결과 해석·배운 것**만 쓴다.
**seed, 정확한 하이퍼파라미터, train/val split 규칙, 실행 커맨드 전문**은
MLflow(비공개 클라우드 VM)에만 남긴다.

**이유** — 작년 적발 사유가 정확히 *"split 시드까지 동일, 학습 파라미터 수치 일치,
주석까지 동일"*이었다. 서사는 베껴가도 그 팀 실험이 되지 않지만, 설정값은 그대로 돌아간다.
포트폴리오 가치는 서사 쪽에 있으므로 잃는 것이 없다.

**비용** — 0. 이미 MLflow를 비공개 VM에 두기로 했으므로 아키텍처에서 그냥 따라 나온다.

**재검토** — 9/23 리더보드 마감 후. 그 시점부터는 전부 공개해도 무방하다.

## D-003. 문서는 MkDocs Material + GitHub Pages, Wiki는 역할 분리

**결정**

| | 담는 것 |
|---|---|
| Pages (`docs/`) | 대회 정보, 실험 기록, 결정 기록 — PR을 거치는 영구 지식 |
| Wiki | 환경 세팅 삽질, 데이터 받는 법, MLflow 접속법, 회의록 — 브라우저에서 바로 고치는 메모 |

**이유** — 둘의 역할이 90% 겹쳐서, 구분하지 않으면 보통 Wiki가 죽는다.
갈리는 지점은 하나다: Wiki는 **git clone/PR 없이 브라우저에서 바로 수정**된다.
그래서 휘발성 메모는 Wiki, 리뷰가 필요한 지식은 Pages로 나눈다.

Jekyll 대신 Material을 쓴 이유는 검색이다. 실험 문서가 수십 개로 늘어나면 검색이 곧 생명이다.

## D-004. 실험 추적은 MLflow 셀프호스팅 (클라우드 VM 상시 구동)

**결정** — 클라우드 VM에 MLflow tracking server를 상시 구동한다.
artifact root는 R2로 보낸다 (D-005).

**이유** — W&B는 팀 협업 시 과금이 붙는다. MLflow는 무료지만 SaaS 백엔드가 없어서
**tracking server가 꺼지면 학습이 실패**한다. 그래서 개인 PC가 아니라 상시 구동
VM이어야 한다.

**주의** — 무료 티어 VM 디스크에 체크포인트를 쌓으면 금방 찬다. artifact는 R2로.

**배포** — 설정을 `infra/mlflow/` 에 코드로 관리하고 Docker Compose로 배포한다(D-010).

## D-010. MLflow는 반드시 인증을 걸고 노출한다

**결정** — `caddy(자동 HTTPS) → mlflow(내장 basic-auth) → postgres` 구성으로 배포한다.
설정은 `infra/mlflow/` 에 코드로 관리한다.

**이유 — 이게 없으면 D-002가 역효과를 낸다**

MLflow 서버는 기본적으로 인증이 없다. 공식 문서상 기본은 로컬 연결만 받고,
외부에 열려면 `--host 0.0.0.0`을 줘야 한다. 즉 **노출하는 순간 아무나 접속 가능**하다.

우리는 D-002에서 "복붙 가능한 설정값은 MLflow에만 둔다"고 정했다. 인증이 없으면
문서에서 일부러 숨긴 seed·하이퍼파라미터·split을 MLflow UI에서 그대로 보게 된다.
완화책이 사라지는 게 아니라 **흩어져 있던 민감 값을 검색 가능한 한 곳에 모아주는**
역효과가 난다. 경쟁팀은 165개다.

`basic_auth.ini` 의 `default_permission` 은 반드시 `NO_PERMISSIONS` 여야 한다.
`READ` 로 두면 익명 읽기가 열린다.

**부수 결정**

| 선택 | 이유 |
|---|---|
| Postgres (SQLite 아님) | 4명 동시 학습 시 SQLite는 `database is locked` 가 난다 |
| Caddy + HTTPS | basic auth 자격증명은 base64 평문. Colab 접속은 공용 경로를 지난다 |
| `--artifacts-destination` (서버 대리 전송) | 클라이언트에 R2 **쓰기** 키를 뿌리지 않아도 된다 |
| `<VM_IP>.sslip.io` | 도메인 없이 Let's Encrypt 발급이 된다 |

**검증 완료** (2026-08-11) — R2 자리에 MinIO를 세워 로컬에서 전 구간을 돌렸다.
컨테이너 기동 → HTTPS → 미인증 401 / 오인증 401 / 정상 200 → run 기록 →
artifact 오브젝트 스토리지 안착까지 확인. 하네스는 `infra/mlflow/compose.test.yml`.

검증 과정에서 배포를 막았을 문제 3개를 잡았다. 셋 다 문서만 보고는 알 수 없었다:

| 증상 | 원인 |
|---|---|
| basic-auth 앱 ImportError → crash-loop | `mlflow` 만으론 부족, `mlflow[auth]` 필요 |
| CSRF secret key 없다며 기동 실패 | `MLFLOW_FLASK_SERVER_SECRET_KEY` 필수 |
| 모든 API 403 `Invalid Host header` | MLflow 3.x 의 DNS rebinding 방어. **기본 허용이 localhost/사설 IP 뿐** |

세 번째가 특히 함정이다 — 로컬에선 통과하고 공개 호스트명에서만 터진다.
`MLFLOW_SERVER_ALLOWED_HOSTS` 를 반드시 지정해야 한다.

인증 실패 시 동작이 **fail-closed** 임도 확인했다. auth 앱이 못 뜨면 인증 없이
서비스되는 게 아니라 컨테이너가 crash-loop 한다.

**아직 미검증** — 실제 VM에서의 Let's Encrypt 발급 (로컬은 Caddy 내부 CA 사용).
MLflow 버전은 검증을 통과한 `3.15.1` 로 고정했다.

**한계** — 인증이 MLflow 내장 한 겹이다. 프록시에 basic auth를 겹치면 클라이언트가
헤더를 하나만 보낼 수 있어 충돌한다. 더 강하게 가려면 Cloudflare Tunnel + Access가
다음 단계이나, Cloudflare에 등록된 도메인이 필요하다.

## D-005. 원본 데이터는 Cloudflare R2에 둔다

**결정** — 데이터셋 원본 보관은 R2. **학습 시에는 스트리밍하지 말고 로컬/네트워크
볼륨에 1회 내려받아서** 돌린다.

**이유** — TFRecord 스트리밍은 매 epoch 전량을 다시 읽는다. 428GB × 10 epoch = 4.28TB.

| 저장소 | egress 단가 | 4.28TB 비용 |
|---|---|---|
| GCS | $0.12/GB | 약 $514 |
| S3 | $0.09/GB | 약 $385 |
| **R2** | **$0.00** | **$0** |

1인 기준이다. 4명이 3트랙을 돌리면 배수로 늘어난다. R2 스토리지는 700~930GB 기준
월 $10~14 수준.

per-epoch 스트리밍은 비용뿐 아니라 GPU를 굶긴다.

**갱신 (2026-08-12)** — 디스크가 156GB뿐이라 "1회 내려받기"가 불가능해졌다.
대역폭을 실측해보니 스트리밍이 오히려 성립한다 → [D-016](#d-016)에서 방침을 바꿨다.
R2를 고른 것이 여기서 결정적으로 작동한다 — egress가 무료라 스트리밍 비용이 0이다.

## D-008. PR은 강제하고, 승인은 강제하지 않는다

**결정** — `main` 브랜치 보호를 켠다.

| 강제함 | 강제 안 함 |
|---|---|
| PR 없이 main 푸시 불가 | 승인 인원 **0명** |
| CI 통과 필수 (`build` + `guard`) | 리뷰 코멘트 해결 |
| force push · main 삭제 불가 | |

설정은 `scripts/setup_repo_protection.sh` 에 코드로 남긴다 (멱등, 재실행 가능).

**이유** — 갈림길은 "PR을 강제할까"가 아니라 **"무엇을 기계가 막고 무엇을 사람에게 맡길까"**다.

- **되돌릴 수 없는 것** — 시크릿 유출, 체크포인트가 히스토리에 박힘, force push로 남의 커밋 증발.
  기계가 막는다. 예외 없음
- **품질 판단** — "이 가설이 타당한가". 새벽 3시에 블로킹할 가치가 없다.
  4명 6주에서 승인 대기는 실제로 비싸고, GitHub은 자기 PR을 자기가 승인할 수 없어서
  required approvals ≥ 1이면 **혼자 작업하는 시간대에 완전히 막힌다**

PR을 강제하는 것만으로도 얻는 게 크다: 모든 변경에 감사 추적이 남고, CI 게이트가 걸리고,
실수로 `git push origin main` 하는 사고가 사라진다.

**부수 결정** — squash 머지 전용 + 머지 후 브랜치 자동 삭제. main 히스토리가 PR당 1커밋이 되어
되돌리기가 쉬워진다.

## D-009. 파일 크기 차단은 CI가 대신한다

**결정** — `.github/workflows/guard.yml` + `scripts/check_diff.py` 로 PR diff를 검사한다.
5MB 초과 파일, 가중치/데이터 확장자, 시크릿으로 보이는 파일명을 차단한다.

**이유** — GitHub의 push ruleset("restrict file size / file extensions")은
**GitHub Team 플랜 + private 레포 전용**이라 우리(Free + public)는 쓸 수 없다.
그런데 이게 유일하게 **되돌릴 수 없는** 사고다:

> 50MB 체크포인트는 GitHub의 100MB 제한을 통과하고 히스토리에 영구히 박힌다.
> 지우려면 force-push 재작성이 필요한데, 4명이 동시에 작업 중이면 사실상 불가능하다.

`.gitignore`와 역할이 다르다. `.gitignore`는 실수로 `git add` 되는 것을 막는 **규약**이고,
이 검사는 규약을 우회했을 때(`git add -f`, .gitignore 추가 이전 커밋, 다른 머신에서 온
브랜치) 잡는 **집행**이다. 겹치는 게 아니라 층이 다르다.

**한계** — PR 검사라 feature 브랜치에 이미 푸시된 객체 자체는 막지 못한다.
다만 main에 병합되지 않으면 브랜치 삭제 후 GC 대상이 된다.

## D-011. 정보가 충돌하면 배포된 코드를 따른다

**결정** — 가이드라인 PDF · 사전설명회 · 배포된 베이스라인/평가 코드가 어긋나면
**배포된 코드와 README를 정본으로 삼는다.**

**이유** — 데이터를 받아보니 PDF가 여러 곳에서 틀렸다:

| 항목 | PDF | 실제 |
|---|---|---|
| 데이터 지역 | 서울 / 제주 | hanam / jeju / livinglab |
| 데이터 기간 | 2024.12, 2025.03 | 2025-02 ~ 2026-04 |

PDF는 대회 시작 전에 쓰였고 코드는 계속 갱신되고 있다. 배포물이 최신이다.

**행동** — 데이터·코드를 실제로 열어본 사람이 문서를 고친다. 문서에 "PDF에는 이렇게
적혀 있지만 실제는 이렇다"를 남겨서, 다음 사람이 같은 혼란을 겪지 않게 한다.

## D-012. 데이터 다운로드 링크는 공개 문서에 적지 않는다

**결정** — 폴더 구조·파일명·받는 순서는 위키에 적되, **Google Drive URL 자체는
팀 채팅에만** 둔다.

**이유** — 주최측이 미공개 Drive 링크로 참가팀에만 배포한 것이다. 우리 위키는 편집은
팀원만 가능하지만 **읽기는 전 세계 공개**다. 여기 적으면 주최측이 선택한 배포 통제를
우회하게 되고, 검색엔진에도 색인될 수 있다.

구조와 파일명만으로도 "무엇을 어떤 순서로 받아야 하는가"는 충분히 전달된다.

## D-013. Planning + 궤적예측에 집중, E2E는 베이스라인 추론 제출까지 {#d-013}

**결정** — O-001을 닫는다. 3트랙 균등 병렬을 포기하고 2트랙에 집중한다.
E2E는 제공된 가중치로 **추론만 돌려 리더보드 점수를 확보**하는 선까지만 한다.

**이유 — 자원 실측 결과**

| | |
|---|---|
| GPU | RTX 5060 Ti 16GB, 드라이버 610.88 |
| 디스크 여유 | **약 156GB** (필요 700GB+) |
| 추가 예산 | 없음 |

- **E2E는 데이터조차 못 받는다.** 250~500GB인데 디스크가 156GB다.
  학습은 주최측 기준 GPU 8장 × 1주일 ≈ 1,300+ GPU시간으로, 5060 Ti 한 장으로는
  산술적으로 불가능하다
- **Planning + 궤적예측은 데이터셋이 동일**하다. 전처리를 한 번만 하면 두 트랙이
  공유하므로 2트랙 비용이 실질 1.3트랙이다
- **수상은 최대 2개 분야**까지다. 2트랙 집중이 상한과 정확히 맞는다

**E2E를 완전히 버리지 않는 이유** — 제공 가중치로 추론만 돌려도 리더보드 점수와
참가 실적이 남는다. 학습을 포기하는 것이지 트랙을 포기하는 것이 아니다.

**재검토** — 디스크나 예산 상황이 바뀌면.

## D-014. 디스크 156GB로 428GB 데이터셋을 다루는 방법 {#d-014}

**결정** — 아카이브 단위 **증분 처리 + 순환 학습**.

```
아카이브 1개 다운로드 → 압축 해제 → 91f 변환 → 원본·압축파일 삭제 → 91f만 보관
```

작업 공간은 아카이브 1개분(~20GB)이면 되고, 누적되는 것은 91f 출력분뿐이다.
가용 디스크로 **약 14개 아카이브 분량**을 동시에 보유할 수 있다
(`livinglab` 9개 전부 + `jeju` 일부 수준).

그 이상이 필요하면 **순환**한다: 세트 A로 N스텝 학습 → 삭제 → 세트 B 내려받아
체크포인트에서 이어서 학습.

**이 방법이 Planning에서 특히 잘 통하는 이유**

베이스라인이 **SAC(off-policy)이고 `buffer_size=1_000_000`** 이다. 모델은 매 스텝
원본 데이터를 읽는 게 아니라 **replay buffer에서 샘플링**한다. 따라서 밑에 깔린
데이터셋을 교체해도 버퍼가 과거 경험을 유지해주므로, 지도학습에서 데이터를 갈아끼울
때처럼 분포가 급격히 흔들리지 않는다. **디스크 제약과 알고리즘이 우연히 잘 맞는다.**

**한계** — 궤적예측(SMART)은 지도학습이라 이 완충 효과가 없다. 전체 셔플이
불가능하므로 데이터 다양성이 성능 상한을 제한한다. 순환 주기를 짧게 가져가는 것으로
일부 완화할 수 있다.

**시작점** — `livinglab`(9개)이 가장 작다. 파이프라인 검증은 여기서.

## D-015. Colab을 쓴다면 GCS가 아니라 Google Drive에서 읽는다 {#d-015}

**결정** — 팀원 중 누구든 Colab을 쓰게 되면 데이터는 **Google Drive**에서 가져온다.
**GCS(Google Cloud Storage) 버킷을 Colab에서 읽지 않는다.**

### 왜 GCS를 금지하는가

기술적 호환은 오히려 GCS가 최고다. 같은 Google 생태계라 인증 한 줄, `gsutil` 기본 설치,
`gcsfuse` 마운트, `tf.data`의 `gs://` 네이티브 지원까지 전부 매끄럽다.

**문제는 요금이 통제 불가능하다는 것이다.** Colab 팀 엔지니어의 공식 답변:

> ["Colab doesn't have a way to control which region your backend is in."](https://github.com/googlecolab/colabtools/issues/880)

버킷과 다른 대륙에 Colab VM이 뜨면 대륙 간 egress가 붙는다. 그 이슈를 올린 사람은
**하루에 $110**이 나왔다 (*"GCP Storage egress between NA and EU"*).

우리 예산은 월 10,000원이다. **하루에 그 15배가 나갈 수 있는 구조**이고,
그 변수를 우리가 고를 수 없다. 싼지 비싼지의 문제가 아니라 통제 불가능한 것에
예산 전체가 걸리는 구조라서 쓰지 않는다.

### Drive는 왜 괜찮은가

Drive → Colab 전송에는 **GB당 egress 과금이 없다.** 그리고 **대회 데이터가 이미
주최측 Drive에 있어서** 어디로 옮길 필요조차 없다. 공유 파일 바로가기는 내 Drive
용량을 소모하지 않는다.

### 단, Drive에도 함정이 있다

| 함정 | 내용 |
|---|---|
| **다운로드 쿼터** | 같은 파일을 반복해서 읽으면 *"Download quota exceeded for this file"* 로 막힌다. 학습은 매 epoch 전량을 다시 읽으므로 정확히 이 패턴이다 |
| **파일 수 한계** | 폴더에 파일이 많으면 작업이 타임아웃되고, 루트에 1만 개가 넘으면 마운트 자체가 실패한다 |

두 번째가 특히 중요하다. 91f 변환 결과는 **약 85,126개 파일**이라 그대로 Drive에
올리면 이 함정에 정면으로 걸린다.

### 그래서 Colab에서 쓸 때의 규칙

1. **원본 아카이브(54개 tar.gz) 단위로 읽는다.** 파일 수가 적어 안전하다
2. 세션 안에서 **Colab 로컬 디스크에 풀고 변환**해서 쓴다 (Drive를 직접 학습 경로로 쓰지 않는다)
3. 변환 결과를 보관하려면 **다시 묶어서(tar) 올린다.** 8만 개 파일을 낱개로 올리지 않는다
4. 체크포인트는 Drive에 저장해서 세션이 끊겨도 이어갈 수 있게 한다

**주 경로는 여전히 [로컬 + R2](#d-016)다.** 이 항목은 Colab을 쓰게 될 경우의 안전 규칙이다.

## D-016. 로컬 GPU + R2 스트리밍을 주 경로로 한다 {#d-016}

**결정** — 데이터는 **Cloudflare R2**에 두고, `rclone mount`로 로컬에 마운트해서
스트리밍 학습한다. 로컬 디스크는 캐시로만 쓴다.

**이유** — 디스크가 156GB뿐인데 데이터는 428GB다([D-014](#d-014)).
그런데 **Waymax는 원래 클라우드 스트리밍용으로 설계됐다** — 기본 데이터셋 경로가
`gs://waymo_open_dataset_motion_v_1_3_1/.../validation_tfexample.tfrecord@150` 형식이다.
즉 스트리밍 학습에 별도 서비스가 필요 없다.

**대역폭 실측 (2026-08-12)**

| 경로 | 속도 |
|---|---|
| GCS | 22.4 MB/s |
| Hetzner (미국) | 9 MB/s |
| 병렬 4개 합산 | **~26 MB/s** |

필요량 추산: SAC 25M 스텝 ÷ 80 = 31만 에피소드. 학습 ~30시간 기준 초당 2.9 에피소드
× 약 5MB ≈ **13 MB/s**. `tf.data`가 병렬 interleave로 읽으므로 **여유가 약 2배**다.

**왜 GCS가 아니라 R2인가**

| | 저장 | egress |
|---|---|---|
| GCS | $0.020/GB | **$0.12/GB** |
| **R2** | **$0.015/GB** | **$0** |

학습 1회에 데이터를 약 3.7회 통과하므로 1.6TB가 나간다. GCS면 **$190**, R2면 **$0**.
R2 스토리지는 428GB 기준 월 약 $6.4(~9,000원)로 예산 안에 들어온다.
읽기 요청 31만 건도 R2 무료 한도(월 1,000만 건) 안이다.

**핵심은 단가가 아니라 사고 가능성이다.** R2는 egress라는 요금 축 자체가 없어서
리전을 잘못 골라 예산이 터지는 일이 구조적으로 불가능하다([D-015](#d-015) 참조).

**구성**

```bash
rclone mount r2:bucket/rideflux_91f /data/rideflux_91f \
    --vfs-cache-mode full --vfs-cache-max-size 100G --dir-cache-time 72h
```

`--vfs-cache-max-size` 로 **로컬 디스크 사용량 상한을 직접 정한다.** 자주 읽는 데이터는
로컬 LRU 캐시에 남고 나머지만 스트리밍된다. 학습 코드는 그냥 로컬 경로로 보므로
`make_waymax_shards.py` 도 그대로 쓸 수 있다.

`gs://` 처럼 네이티브로 읽히지 않아 `rclone mount` 한 겹이 필요한 것이 R2의 단점이지만,
그 대가로 egress 사고 위험이 사라진다.

**미검증** — R2→한국 실측 속도, `--vfs-cache-mode full` 에서 `tf.data` 병렬 읽기가
잘 붙는지, 91f 변환 후 실제 총 용량. **버킷 만들고 100MB 올려서 재보는 것이 첫 단계다.**

## D-017. 학습 코드는 이 레포에 두지 않는다 — 트랙별 private 저장소 {#d-017}

**결정** — 학습 코드는 `fighting-team-tree` org의 **트랙별 private 저장소 3개**에 둔다.
이 레포에는 두지 않는다.

| 트랙 | 저장소 | 베이스라인 |
|---|---|---|
| 모션 플래닝 | `adc2026-planning` | `jaehyuck0103/V-Max` 복제 |
| 미래궤적 예측 | `adc2026-prediction` | 주최측 배포 tarball |
| E2E 주행 | `adc2026-e2e` | 주최측 배포 tarball |

**이유 1 — [D-002](#d-002)가 코드에서 무너진다**

이 레포는 public이다([D-001](#d-001)). 문서에서 하이퍼파라미터를 빼도 학습 코드를 같이 두면
`config.yaml`과 `train.py`에 seed·split·LR이 그대로 박힌 채 공개된다.
작년 적발 사유가 정확히 그것이었다. 문서만 조심하고 코드를 공개하는 것은 앞문만 잠그는 것이다.

**이유 2 — 베이스라인이 fork 구조라 복사하면 upstream이 끊긴다**

세 트랙 베이스라인은 각각 별도 배포물이다([D-007](#d-007)의 연장). 이 레포로 복사해오면
대회 중 베이스라인 패치가 나왔을 때 `git fetch upstream`이 불가능해지고, 손으로 머지해야 한다.
6주 일정에서 순수 손실이다.

**이유 3 — 트랙끼리도 합치지 않는다**

CUDA 버전부터 갈린다(E2E 12.8 / Planning 13). 모노레포로 묶으면 환경이 충돌하고
Planning의 upstream 추적이 끊긴다. 저장소 3개를 관리하는 비용보다
되돌릴 수 없는 divergence가 비싸다.

**추적성은 끊기지 않는다 — 이게 이 결정이 성립하는 근거다**

`AGENTS.md`의 3각 연결에서 코드 쪽 고리는 **MLflow가 자동 기록하는 git commit hash**다.
즉 *"이 점수를 낸 코드가 정확히 무엇인가"* 에 답하려면 코드가 **어딘가 커밋되어 있기만** 하면
되지, **이 레포에** 있을 필요가 없다. 불변 참조는 저장소 경계를 넘어간다.

각 저장소는 브랜치 규칙(`exp/<EXP-ID>-<slug>`)을 이 레포와 공유하고,
학습 코드에 `mlflow.set_tag("exp_id", ...)` 를 넣는다.

**`baseline-vanilla` 태그를 반드시 단다**

세 저장소 모두 **베이스라인 원본을 아무것도 고치지 않은 상태**로 첫 커밋에 올리고
`baseline-vanilla` 태그를 단다. `git diff baseline-vanilla..HEAD` 가 곧
"우리가 무엇을 바꿨는가"의 완전한 답이 되고, 본선 4팀 코드 검증에서 정확히 그것을 묻는다.

**첫 커밋에 우리 수정을 섞으면 이 기준선은 영영 만들 수 없다.**
Prediction·E2E는 GitHub에 upstream이 없는 tarball 배포물이라 여기서 더 중요하다.
(엄밀히 말해 fork인 것은 Planning뿐이고, 나머지 둘은 "배포물이 첫 커밋"이다.)

**감수하는 것** — 저장소가 4개로 늘어 clone·환경 설정 진입 비용이 생긴다.
위키 [학습 코드 레포](https://github.com/fighting-team-tree/autonomous-driving-challenge-2026/wiki/학습-코드-레포)
페이지로 완화한다.

**예외** — 세 트랙에 공통으로 쓰는 배관(R2 동기화, 제출 포맷 변환)은 이 레포 `scripts/`에 둘 수 있다.
설정값이 아니라 도구이고, 트랙 저장소 어디에 넣어도 중복된다.
단 [D-007](#d-007)에 따라 **실제로 두 트랙 이상에서 쓰게 됐을 때** 옮긴다. 미리 만들지 않는다.

**재검토** — 9/23 리더보드 마감 후. 그 시점부터는 세 저장소를 public으로 열어도 무방하고,
정리된 실험 서사(이 레포) + 실제 코드(트랙 저장소) 조합이 포트폴리오로는 더 낫다.
