## D-001. 저장소를 public으로 유지한다

**결정** — 대회 기간 중에도 저장소를 공개로 둔다.

**이유** — 후원 기업 15곳 면접 기회가 걸려 있고, 정리된 실험 로그는 그 자체로 포트폴리오다.
비공개로 두면 GitHub Pages가 동작하지 않는다 (org가 free plan이라 private Pages는
GitHub Team 이상 필요).

**감수하는 리스크** — 경쟁팀 165개에 가설이 실시간 노출된다. 주최측이
[작년 표절 적발 사례](competition/briefing.md#plagiarism)를 명시적으로 경고했고,
본선 4팀은 코드 검증을 받는다.

**완화** — D-002 참조.

## D-002. 복붙 가능한 설정값은 문서에 쓰지 않는다

**결정** — 공개 문서에는 **가설·설계 의도·결과 해석·배운 것**만 쓴다.
**seed, 정확한 하이퍼파라미터, train/val split 규칙, 실행 커맨드 전문**은
MLflow(비공개 클라우드 VM)에만 남긴다.

**이유** — 작년 적발 사유가 정확히 *"split 시드까지 동일, 학습 파라미터 수치 일치,
주석까지 동일"*이었다. 서사는 베껴가도 그 팀 실험이 되지 않지만, 설정값은 그대로 돌아간다.
포트폴리오 가치는 서사 쪽에 있으므로 잃는 것이 없다.

**비용** — 0. 이미 MLflow를 비공개 VM에 두기로 했으므로 아키텍처에서 그냥 따라 나온다.

**재검토** — 9/23 리더보드 마감 후. 그 시점부터는 전부 공개해도 무방하다.

## D-003. 문서는 MkDocs Material + GitHub Pages, Wiki는 역할 분리

**결정**

| | 담는 것 |
|---|---|
| Pages (`docs/`) | 대회 정보, 실험 기록, 결정 기록 — PR을 거치는 영구 지식 |
| Wiki | 환경 세팅 삽질, 데이터 받는 법, MLflow 접속법, 회의록 — 브라우저에서 바로 고치는 메모 |

**이유** — 둘의 역할이 90% 겹쳐서, 구분하지 않으면 보통 Wiki가 죽는다.
갈리는 지점은 하나다: Wiki는 **git clone/PR 없이 브라우저에서 바로 수정**된다.
그래서 휘발성 메모는 Wiki, 리뷰가 필요한 지식은 Pages로 나눈다.

Jekyll 대신 Material을 쓴 이유는 검색이다. 실험 문서가 수십 개로 늘어나면 검색이 곧 생명이다.

## D-004. 실험 추적은 MLflow 셀프호스팅 (클라우드 VM 상시 구동)

**결정** — 클라우드 VM에 MLflow tracking server를 상시 구동한다.
artifact root는 R2로 보낸다 (D-005).

**이유** — W&B는 팀 협업 시 과금이 붙는다. MLflow는 무료지만 SaaS 백엔드가 없어서
**tracking server가 꺼지면 학습이 실패**한다. 그래서 개인 PC가 아니라 상시 구동
VM이어야 한다.

**주의** — 무료 티어 VM 디스크에 체크포인트를 쌓으면 금방 찬다. artifact는 R2로.

## D-005. 원본 데이터는 Cloudflare R2에 둔다

**결정** — 데이터셋 원본 보관은 R2. **학습 시에는 스트리밍하지 말고 로컬/네트워크
볼륨에 1회 내려받아서** 돌린다.

**이유** — TFRecord 스트리밍은 매 epoch 전량을 다시 읽는다. 428GB × 10 epoch = 4.28TB.

| 저장소 | egress 단가 | 4.28TB 비용 |
|---|---|---|
| GCS | $0.12/GB | 약 $514 |
| S3 | $0.09/GB | 약 $385 |
| **R2** | **$0.00** | **$0** |

1인 기준이다. 4명이 3트랙을 돌리면 배수로 늘어난다. R2 스토리지는 700~930GB 기준
월 $10~14 수준.

per-epoch 스트리밍은 비용뿐 아니라 GPU를 굶긴다. Runpod는 같은 DC의 network volume을 쓴다.

## D-006. 규칙 정본은 `AGENTS.md` 하나

**결정** — `AGENTS.md`가 유일한 정본. `CLAUDE.md`는 `@AGENTS.md` 한 줄로 import하고,
`docs/conventions.md`는 snippets로 include해 Pages에 렌더한다.

**이유** — Claude Code는 [공식 문서상 `CLAUDE.md`만 읽고 `AGENTS.md`는 읽지 않는다](https://code.claude.com/docs/en/memory).
반면 Codex CLI·Copilot·Cursor·Gemini CLI 등은 `AGENTS.md`를 네이티브로 읽는다.
사람용 문서와 에이전트용 파일을 따로 쓰면 2주 안에 갈라지므로 include로 묶었다.

Windows 팀원을 고려해 심볼릭 링크 대신 `@AGENTS.md` import를 썼다
(심볼릭 링크는 Windows에서 관리자 권한 필요).

## D-007. `src/` 를 미리 만들지 않는다

**결정** — 코드 폴더를 미리 스캐폴딩하지 않는다.

**이유** — 세 트랙의 베이스라인(V-Max / SMART / VAD)은 각각 별도 저장소를 fork해서
쓰는 구조다. 미리 판 폴더는 안 쓰이거나 규칙만 어긋난다. 실제로 필요할 때 만든다.

## D-008. PR은 강제하고, 승인은 강제하지 않는다

**결정** — `main` 브랜치 보호를 켠다.

| 강제함 | 강제 안 함 |
|---|---|
| PR 없이 main 푸시 불가 | 승인 인원 **0명** |
| CI 통과 필수 (`build` + `guard`) | 리뷰 코멘트 해결 |
| force push · main 삭제 불가 | |

설정은 `scripts/setup_repo_protection.sh` 에 코드로 남긴다 (멱등, 재실행 가능).

**이유** — 갈림길은 "PR을 강제할까"가 아니라 **"무엇을 기계가 막고 무엇을 사람에게 맡길까"**다.

- **되돌릴 수 없는 것** — 시크릿 유출, 체크포인트가 히스토리에 박힘, force push로 남의 커밋 증발.
  기계가 막는다. 예외 없음
- **품질 판단** — "이 가설이 타당한가". 새벽 3시에 블로킹할 가치가 없다.
  4명 6주에서 승인 대기는 실제로 비싸고, GitHub은 자기 PR을 자기가 승인할 수 없어서
  required approvals ≥ 1이면 **혼자 작업하는 시간대에 완전히 막힌다**

PR을 강제하는 것만으로도 얻는 게 크다: 모든 변경에 감사 추적이 남고, CI 게이트가 걸리고,
실수로 `git push origin main` 하는 사고가 사라진다.

**부수 결정** — squash 머지 전용 + 머지 후 브랜치 자동 삭제. main 히스토리가 PR당 1커밋이 되어
되돌리기가 쉬워진다.

## D-009. 파일 크기 차단은 CI가 대신한다

**결정** — `.github/workflows/guard.yml` + `scripts/check_diff.py` 로 PR diff를 검사한다.
5MB 초과 파일, 가중치/데이터 확장자, 시크릿으로 보이는 파일명을 차단한다.

**이유** — GitHub의 push ruleset("restrict file size / file extensions")은
**GitHub Team 플랜 + private 레포 전용**이라 우리(Free + public)는 쓸 수 없다.
그런데 이게 유일하게 **되돌릴 수 없는** 사고다:

> 50MB 체크포인트는 GitHub의 100MB 제한을 통과하고 히스토리에 영구히 박힌다.
> 지우려면 force-push 재작성이 필요한데, 4명이 동시에 작업 중이면 사실상 불가능하다.

`.gitignore`와 역할이 다르다. `.gitignore`는 실수로 `git add` 되는 것을 막는 **규약**이고,
이 검사는 규약을 우회했을 때(`git add -f`, .gitignore 추가 이전 커밋, 다른 머신에서 온
브랜치) 잡는 **집행**이다. 겹치는 게 아니라 층이 다르다.

**한계** — PR 검사라 feature 브랜치에 이미 푸시된 객체 자체는 막지 못한다.
다만 main에 병합되지 않으면 브랜치 삭제 후 GC 대상이 된다.
