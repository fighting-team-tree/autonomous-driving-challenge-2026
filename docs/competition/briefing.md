## 공략 포인트 {#attack-points}

### 궤적예측 — 베이스라인이 의도적으로 최적화되지 않았다

가장 큰 기회입니다. 담당자(지명인 책임)가 직접 말한 내용:

> *"베이스라인 코드가 826 GFLOPs 이렇게 돼 있는데, 제가 저거를 열심히 해서 더 낮춰볼까 생각을 하기도 했다가 '아 그냥 이대로 하자' 해서 **꽤 넉넉하게 베이스라인 컷오프를 만들어 놨어요.** 그래서 참여하시는 분들은 **개선의 여지가, 일단 연산량에서 굉장히 많다**라는 걸 생각해 주시면 될 것 같고"*

- 베이스라인 SMART: **826 GFLOPs, 추론 515ms**
- 컷오프는 베이스라인 FLOPs의 **3배**
- Error Score는 **100ms 이하면 페널티 없음**. 515ms는 페널티를 크게 먹고 있는 상태

즉 정확도를 그대로 두고 **경량화만 해도 점수가 오르는 구조**입니다. 담당자가 제안한 방향:
토큰화 구조 최적화, 6개 모드 예측 부분의 최적화.

### E2E — 테스트 시에도 5초 뒤 목표점이 주어진다

Q&A에서 확인된 내용입니다. PDF만 봐서는 알 수 없습니다.

> *"현재 프레임은 (0, 0)으로 제공이 되고, 말씀하신 **5초 후에 타겟 포인트가 XY 좌표까지 상대 좌표계로 미터 단위로 제공**됩니다."* — 테스트에서도 동일

입력 구성: **과거 3초 + 현재 + 미래 5초 지점의 목표점 1개.** 사실상 goal-conditioning 신호가
공짜로 주어지는 셈이라, 이걸 안 쓰는 모델은 손해입니다.

추가로:

- **신호등 데이터는 이번 대회에 미포함**
- 핵심은 **3D 맵**. 2D 맵(횡단보도·정지선·반대쪽 차로·연석)은 선택적 보조이며,
  *"이것만 가지고 학습하면 3D 맵보다 성능이 낮을 가능성이 많다"*
- 라이다·IMU·GPS 원본은 **제공되지 않음** (치팅 방지)

### Planning — 기준선과 실격 조건

배포되는 세 가지 기준선:

| 기준선 | 총점 | 설명 |
|---|---|---|
| 사람 운전 기록 | ≈ 1.0 | 진행도 100%. 충돌은 주차 차량 스쳐지남이 인정된 것 |
| SAC 예제 (배포) | ≈ 80 | 미완성 구현 — 제공 상태를 다 쓰지 않고 손실에 승차감 미반영 |
| 등속 모델 | ≈ 60 | 마지막 상태 유지. **여기 근처면 뭔가 잘못된 것** |

담당자 예상: *"참가자는 적어도 이것보다는 좋은 모델을 제출할 것이기 때문에 약 90점 정도"*

!!! danger "0점 처리 조건"
    - **제출물이 실행되지 않으면 즉시 0점**
    - 전체 평가 제한 시간 초과 시 0점
    - 평가 중 **NaN 등 예외 발생 시 해당 배치가 점수로 처리되지 않음**

    배포된 테스트 코드로 **반드시 사전 검증**하고 올릴 것. 제출 5회 중 한 번을 실행 오류로
    날리는 것이 가장 아까운 손실입니다.

## 공통 사항 {#common}

### 허용되는 것

- 제공 학습 프레임워크 대신 **자체 프레임워크 사용 가능**. 단 제출물이 평가 코드에서 돌아가야 함
- **외부 공개 데이터셋 자유 사용** (WOMD, nuPlan 등). 사용 내역만 제출
- **제공 라벨 수정 자유**
- 학습 기간 제한 없음 — Q&A에서 *"일주일 이상 걸려도 재현만 되면 괜찮다"* 확인
- 궤적예측 데이터가 부족하면 30.1초 원본을 9.1초 3개로 쪼개 3배로 늘려 써도 됨

### 금지되는 것

- **테스트셋에 라벨을 만들어 학습에 쓰는 것** — 원천 금지
- 사전 학습 백본을 바꿨다면 변경 내역 제출 필요

### 재현성 허용 오차

> *"1등이 재현성 평가를 한다 하면 **2등과 순위가 바뀌지 않을 정도**, 그 정도 내에서 재현된다면 합리적"*

E2E는 A6000 / 4090 / 5090 / B200에서 사전 테스트했고 **동일 성능**이 나오므로,
시드에 따른 미세한 추론 차이가 L2에 영향을 주지 않는다고 확인됐습니다.

!!! danger "작년 실제 사례"
    > *"작년 기준으로 좀 불미스러운 일이 있었어요. 어떤 두 팀이 사이좋게 코드를 좀 이렇게
    > 공유를 많이 하신 것 같은데, **train/validation 분할이 시드까지 동일**하다든가,
    > **학습 파라미터 수치가 되게 일치**한다든가, 심지어 **설명 주석까지 사실상 동일**하다든가.
    > 나중에 본선의 4개 팀에 대해서는 코드 검증까지 다 이루어질 예정이니, 이런 것들이
    > 적발돼서 혹시 좀 불미스럽게 탈락이 되는 일이 없었으면"*
    >
    > *"이 부분은 2번 과제뿐만 아니라 1번, 3번 과제도 동일합니다."*

**우리 저장소는 public입니다.** 그래서 규칙을 하나 둡니다:

- 문서(공개)에는 **가설과 배운 것**을 쓴다 — 서사이므로 베껴가도 그 팀 실험이 되지 않는다
- MLflow(비공개 VM)에는 **seed, 정확한 하이퍼파라미터, split, 체크포인트**를 남긴다

자세한 내용은 [작업 규칙](../conventions.md)에 있습니다.

## 연구 동향 세미나 요약 (국민대 김산민 교수)

트랙 공략에 직접 쓰이진 않지만 접근 방향을 잡는 데 참고할 내용입니다.

- 자율주행은 **모듈러 → E2E 과도기**. 모듈러의 근본 문제는 **error accumulation** —
  인지·판단·제어가 독립 학습되고 나중에 합쳐지면서 오차가 누적됨
- 최근 흐름은 **듀얼 시스템**: VLM/VLA가 저주파(low frequency)로 상식·맥락을 담당하고,
  E2E 모델이 고주파(high frequency)로 궤적을 생성하는 slow-fast 구조
- VLM은 자율주행 전용으로 학습된 모델이 아니므로 그대로 붙이면 한계가 있고,
  주행 맥락 이해를 향상시키는 연구가 진행 중
- 경로 후보를 만들고 **safety scoring**으로 거르는 방식 — 벽에 닿는 후보는 0점 처리
- E2E vs VLA는 택일 문제가 아니라 함께 가는 방향

## 운영 안내

- 대회는 올해 3회차. 1회차(2024)는 객체 검출 중심, 2회차는 객체 인지·추적·예측 중심,
  이번 3회차는 **예측 고도화 및 주행 의사결정** 중심
- 4회차 계획: E2E 전방위 멀티센서 기반 3D 객체·차선 인식, E2E 드라이빙 하드케이스 포함
- **Q&A 오픈채팅방** 운영 (10~17시). 실시간 답변 아니고, **중복 질문에는 답변하지 않으므로
  기존 기록을 먼저 확인**할 것
