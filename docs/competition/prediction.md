# 트랙 2 — 자율차 주변 미래궤적 예측

주변 동적 객체의 **과거 1초** 움직임을 기반으로 **향후 8초**의 미래 궤적을 예측합니다.

담당: ETRI 지명인 책임 (myungin@etri.re.kr)

!!! success "세 트랙 중 개선 여지가 가장 명확한 트랙"
    담당자가 베이스라인을 **의도적으로 최적화하지 않았다고 직접 밝혔습니다.**
    자세한 인용은 [사전설명회 정리](briefing.md#attack-points)에 있습니다.

## 입출력

| | |
|---|---|
| 입력 | 과거 1초 + 현재 상태(current state) + 지도 |
| 출력 | 주변 에이전트별 **미래 8초 궤적, 후보 6개** (K=6) |

예측 대상 에이전트는 **JSON 파일로 명시**되어 제공됩니다. 현재 시점 기준으로 보이는
에이전트의 미래 궤적을 예측하면 됩니다.

## 데이터셋

[모션 Planning](planning.md#dataset)과 **완전히 동일**합니다. 전처리 파이프라인을 공유하세요.

- 학습: **85,000 scene 이상** (GT 포함)
- 테스트: **4,300 scene** (하남·제주만). GT 미포함
- **예측해야 할 에이전트 수: 32,825개**
- 테스트 데이터는 학습셋 **이후 시기**에서 추출됨

### Waymo 데이터셋과 다른 점

- 기본 포맷은 Waymo Open Dataset과 거의 동일 → 필드 구성을 먼저 확인할 것
- **road graph 표현 방식이 다릅니다.** 타입별로 보면 다 이어져 보이지만,
  **ID별로 보면 road segment가 서로 구분**됩니다. ID와 타입을 적절히 조합하면
  더 풍부하게 표현할 수 있습니다. pkl 파일을 열어보면 금방 이해됩니다
- 데이터셋 상세는 함께 제공되는 **MD 파일** 참고

### 데이터 늘리기

원본은 30.1초인데 9.1초로 크롭해서 씁니다. 데이터가 부족하면
**30.1초를 9.1초 3개로 쪼개 3배로 늘려도 됩니다.**
다만 담당자 경고: *"85,000개 할 때도 짧게 걸리지 않더라. 며칠 정도 생각하고 돌려보라."*

## 평가

### 1차 (Cut-off)

- 지표: **minADE₆**
- 제공 베이스라인 대비 **연산량(FLOPs) 3배 초과 시 탈락**

### 2차 (최종 점수) — Error Score, 낮을수록 우수

정확도(minADE₆)와 추론 속도($T_{infer}$)를 결합합니다.

- **$T_{infer}$가 100ms 이하면 Error Score가 증가하지 않습니다**
- 100ms를 초과하면 초과분에 비례한 가중치로 감점
  (150ms → 1.25배, 200ms → 1.5배)
- $T_{infer}$: 단일 Scene당 추론 시간 (ms, NVIDIA RTX 4090 기준)

### minADE₆ 가 무엇인가

모델이 낸 **K개 후보 궤적 중 GT와 가장 오차가 적은 궤적**의 거리 오차 평균입니다.
`minADE₁`은 그냥 ADE와 같습니다.

예: 교차로에서 모델이 "완만한 직진 / 좌회전 / 감속 / 정지 / …" 6개 후보를 냈고
GT가 좌회전이면, 좌회전 후보와의 오차만 점수에 반영됩니다.

과거 1초만으로 교차로 거동을 맞히는 것은 애매하기 때문에, **다중 모드 예측**으로
모델 성능을 정확히 평가하려는 설계입니다.

## 제출

- **`.npz` 파일** 제출 (`submission.npz`). 제출 코드도 함께 제공됨
- 포함 내용: 예측 대상 에이전트 ID, 6개 후보 미래 궤적, scene 이름, $T_{infer}$
- **FLOPs와 추론 시간은 코드가 자동 계산해서 dict로 기록**합니다. 그대로 제출하면
  서버가 검사합니다
- 상세 포맷은 함께 제공되는 **submission MD 파일** 참고

## 베이스라인 — SMART

[SMART](https://github.com/rainmaker22/SMART): *Scalable Multi-agent Real-time Motion
Generation via Next-token Prediction* (NeurIPS 2024, **Waymo Open Sim Agents Challenge
2024 우승 모델**)

움직임과 지도를 **언어 모델처럼 토큰화**해서 다음 움직임을 추론하는 구조입니다.
담당자 평: *"약간 무거운 경향이 있지만 정확도는 꽤 괜찮다."*

### 베이스라인 수치 — 여기가 공략 지점

| 항목 | 값 |
|---|---|
| FLOPs | **826 GFLOPs** |
| 추론 시간 | **515 ms** |
| Cut-off | 베이스라인 FLOPs의 3배 |
| 페널티 없는 구간 | **100 ms 이하** |

515ms는 페널티를 크게 먹고 있는 상태입니다. **정확도를 유지한 채 경량화만 해도
Error Score가 개선**됩니다.

### 원본 SMART에서 수정된 것 (베이스라인 코드에 이미 반영됨)

- 챌린지 데이터에 맞춘 전처리: 30.1초 → 9.1초 크롭
- **코드북 재생성** (토큰 기반 추론용)
- 학습 중 어텐션 값 폭주 방지, NaN 제거
- **K=6 후보 궤적 출력** — 원본 SMART에는 없던 기능
- 대상 에이전트 처리, 학습 안정화, 고속화

### 전처리기

TensorFlow/protobuf 없이 쓸 수 있도록 **전용 파이썬 전처리기**가 포함돼 있습니다.
TFRecord → 파싱 → 로딩 → 9.1초 크롭 → 현재 시점 기준 필터링 → pkl 저장.

실환경 데이터라 현재 시점에 한 프레임 정도 안 보이는 에이전트가 있는데,
**선형 보간으로 위치·헤딩·속도를 채우는 처리도 포함**돼 있습니다.

## 이 트랙의 초기 가설 후보

> 실제 실험은 [실험 기록](../experiments/index.md)에 `EXP-M00N` 으로 등록하세요.

- **경량화 우선.** 826 GFLOPs / 515ms는 담당자가 손대지 않았다고 명시한 지점.
  100ms 목표로 줄이면 정확도가 다소 떨어져도 Error Score는 개선될 수 있음
- 담당자가 언급한 최적화 후보: **토큰화 구조**, **6-mode 예측 부분**
- road graph의 **ID + 타입 조합**을 활용한 표현 개선 (Waymo와 다른 부분이라
  원본 SMART가 활용하지 못하고 있을 가능성)
- 데이터 3배 증강(30.1초 → 9.1초 × 3)의 실효 확인
