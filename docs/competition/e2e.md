# 트랙 3 — E2E Driving

멀티 카메라로 주행 콘텐츠(객체, 맵)를 인식하고, 이를 바탕으로 자율주행 차량의
미래 주행 궤적을 **End-to-End 방식으로** 생성합니다.

담당: ETRI 김진우 책임 (jwkim81@etri.re.kr)

## 입출력 — 목표점이 주어진다

| | |
|---|---|
| 입력 | 과거 3초 + 현재 프레임 1개 + **미래 5초 지점의 목표점 1개** |
| 출력 | 미래 3초 Ego 궤적 |

!!! tip "테스트에서도 목표점이 제공됩니다"
    Q&A에서 확인된 내용입니다. 현재 프레임이 (0, 0)이 되는 **상대 좌표계**로,
    5초 뒤 목표점의 XY가 **미터 단위**로 주어집니다. 학습·테스트 모두 동일합니다.

    사실상 goal-conditioning 신호가 공짜로 주어지는 셈이라, 활용하지 않으면 손해입니다.

## 데이터셋

- **총 140,000 프레임** (학습 112,000 / 테스트 28,000). 용량 **250~500GB** (라이다 제외)
- 센서: 오토모티브 카메라(AR0341AT) **6대** + 라이다 Hesai Pandar128(**데이터 비공개**)
- 수집 주기: **10Hz** (카메라·라이다 동기화)
- 수집 지역: 대전 ETRI, 대전 신세계 도시 백화점, 세종까지 이어지는 고속화도로 등 실도심
- Train 내 validation 비율은 참가자가 자율 결정
- 테스트 라벨 비공개

### Scene 구성

- 학습 단위를 **시나리오**로 정의. Raw long take를 **30초 단위**로 분할, **300프레임**
- 전후 파악을 위해 앞 5초 + 뒤 5초가 붙어 **총 40초** 분량
- 이미지는 JPEG 압축으로 제공

```
/CHALLENGE_DATASET/
└── {YYYYMMDD}-{HHMMSS}/          # 시나리오 폴더 (예: 20260213-112815)
      ├── camera_front/
      │    ├── 00000000.jpg ... 00000299.jpg
      ├── camera_front_left/
      ├── camera_front_right/
      ├── camera_rear_left/
      ├── camera_rear_right/
      ├── camera_rear_wide/
      ├── calibration/calibration.parquet
      ├── meta/timestamps.parquet
      └── annotation/
           ├── object.parquet
           ├── map.parquet
           └── ego_pose.parquet
```

### 라벨

| 분류 | 항목 | 내용 |
|---|---|---|
| Perception | 3D 객체 | Vehicle / Pedestrian / Cyclist(자전거·바이크 포함) 3D 박스 + **트래킹 ID** |
| Perception | Agent Trajectory | 주변 동적 객체의 미래 주행 궤적 |
| Perception | 맵 요소 | 차선 Geometry |
| Planning | Ego Trajectory | Ego 차량 미래/과거 주행 궤적 |

클래스를 3개로 단순화한 이유: *"트래킹이 잘 되려면 클래스 개수가 너무 많아지면
왔다 갔다 하는 부분들이 있습니다."* 필요하면 크기 기준으로 세분화하는 기법을 쓰라는 안내.

Ego는 고정밀 GPS + IMU 보정 + 후처리 로컬라이제이션으로 정렬돼 있습니다.

### 데이터 품질 — 담당자 설명

- **약 90%를 버렸습니다.** 이미지-라인 정합(alignment)과 로컬라이제이션이 잘 된 부분만 배포
- 오토라벨링 후 **전문 라벨러 5명이 5개월**, 연구진 3~4명이 샘플링·검수
- 3D 객체는 무거운 모델로 두 달간 학습시켜 생성. 그럼에도 오검출이 일부 남아있을 수 있음
- 차선은 라이다 기준 오토라벨링. 전제 조건인 **extrinsic calibration을 최소 월 1회 점검** —
  계절에 따라 카메라 구조물이 수축·팽창하며 틀어지기 때문. 매 세트마다 파라미터가 조금씩 다름
- **중앙선이 2개면 2개로 정확히 맞춤** (하나로 합치지 않음). 프로젝션 시 이미지 피처와
  매칭되어 표현되기 때문에 엉뚱한 곳에 라인이 그려지면 문제가 됨

### 맵 — 3D가 핵심

| | 포함 | 비고 |
|---|---|---|
| **3D 맵** (핵심) | 자차 주행 경로에서 보이는 방향의 차선 | 이미지와 정합이 맞음 |
| 2D 맵 (선택) | 횡단보도, 정지선, 반대쪽 차로, 연석 바운더리 | 3D에 빠진 요소 보완 |

!!! warning "2D 맵만으로 학습하지 말 것"
    > *"이것만 가지고 나는 트레이닝 할 거야 라고 하면 저희가 드리는 3D 맵보다
    > 성능이 낮을 가능성도 많다."*

    2D는 보조로 쓰되, 정지·교차로·횡단보도 시나리오에서 활용도가 있다는 것이 담당자 조언입니다.

### 제공되지 않는 것

- **신호등 데이터** — 이번 대회 미포함
- 라이다 원본, IMU, GPS, 로케인 데이터 — **치팅 방지 목적**
- HD맵 차선 연결 관계 토폴로지
- 테스트셋의 타임스탬프, 날짜, 시나리오 ID, 라벨, 미래궤적 GT

## 평가

### 1차 (Cut-off)

- 지표: **nuScenes E2E Planning의 L2(m)**
- 베이스라인 대비 **연산량(FLOPs) 3배 초과 시 탈락**

$$
L2 = \frac{1}{T}\sum_{t=1}^{T} \lVert \hat{p}_t - p_t \rVert_2
$$

$\hat{p}_t$ = 예측 Ego 위치, $p_t$ = GT, $T$ = 평가 미래 궤적 포인트 수.
**미래 3초** 기준입니다 (담당자: *"3초가 충분하냐? 충분하지 않죠. 챌린지 범위 내에서 3초"*).

### 2차 (최종 점수) — Error Score, 낮을수록 우수

L2와 추론 속도($T_{infer}$)를 결합합니다.

- **100ms 이하면 Error Score가 증가하지 않음**
- 초과 시 비례 가중치로 감점 (150ms → 1.25배, 200ms → 1.5배)
- $T_{infer}$: 단일 Scene당 추론 시간 (ms, RTX 4090 기준)

## 제출

**본선 1차** — 지정 형식의 추론 결과 파일

**본선 2차** (별도 공지 예정)

- 개발한 **Docker 이미지**
- 리더보드 성능에 해당하는 **체크포인트**
- **모델 코드**
- 리더보드 제출 시 사용한 **추론 코드**
- 리더보드 제출 시 사용한 **FLOPs 측정 코드**
- 외부 공개 데이터 사용 시 **어떤 데이터를 얼마나 썼는지 보고서**
  (사용 자체에 페널티는 없고 확인 목적)
- 사전학습 백본을 바꿨다면 변경 내역

## 베이스라인 — VAD-tiny

[VAD](https://github.com/hustvl/VAD): *Vectorized Scene Representation for Efficient
Autonomous Driving* (ICCV 2023)

선정 이유 (담당자): *"여러분이 만드신 모델이 이것보다는 성능이 좋을 것이라는 기대치가
있었고, 실시간으로 돌아가는 부분을 100ms 정도라고 생각했기 때문에 최대한 가볍고 빨리
돌아갈 수 있는 모델을 one of them으로 선택했다."*

| | |
|---|---|
| Cut-off | VAD-tiny 대비 **FLOPs 3배까지 허용** |
| 페널티 없는 구간 | **100ms 이하** |
| 학습 소요 | **GPU 8장 서버로 약 1주일** |

- **Docker 환경 제공.** 이미지 빌드 → 컨테이너 실행 → 데이터 변환 → 학습
- 데이터는 BEV 기준 구성이라 바로 학습 가능
- 제공 스크립트는 **단일 GPU 기준**이므로 숫자만 바꿔 멀티 GPU로 쓰면 됨
- 코드에 **web 파일**이 포함돼 있어 Q&A와 상세 확인 가능
- **VAD 외 다른 모델 사용 자유**

## 이 트랙의 초기 가설 후보

> 실제 실험은 [실험 기록](../experiments/index.md)에 `EXP-E00N` 으로 등록하세요.

- **5초 목표점을 명시적 조건으로 주입.** 테스트에서도 제공되므로 안 쓰면 손해
- FLOPs 3배 여유가 있으므로 **정확도 쪽으로 예산을 쓰되 100ms 선은 지키는** 균형점 탐색
- 2D 맵(횡단보도·정지선)을 보조 입력으로 추가했을 때 정지·교차로 시나리오 개선 여부
- 신호등 정보가 없으므로 정지 상황 판단을 무엇으로 대체할지

!!! warning "자원 격차 확인 필요"
    베이스라인 학습이 **8-GPU 서버로 1주일**입니다. 보유 자원(3060/5060, Colab, Runpod)과
    격차가 큽니다. 8/18 첫 제출로 베이스라인 점수를 확인한 뒤 투입 비중을 재평가하는
    항목이 [결정 기록](../decisions.md)에 열려 있습니다.
